2. Explorer 图谱界面

左侧导航从上到下：总览、本体管理、知识存储、知识加工、知识治理、知识应用、决策因果。

图谱浏览页（图超过 5,000 实体时）先显示「从一个实体开始浏览」：

  1. 搜索后选择实体，或点「常用入口」（连接最多的实体），画布上只画它的邻居；
  2. 选中实体后用画布左上角「展开邻居」「展开两层」往外扩，「清空画布」重来；
  3. 要看整张图点「加载全图」（较慢，几分钟），或在地址后加 ?full=1；
  4. 全图画布：顶部搜索框；「全图 / 分组视图 / 聚焦」；「效果」「邻居」「时序」；「距离」里的热力图和中心视图；底部时间轴；
  5. 点节点打开检视面板：内容、操作（含「运行关系预测」）、路径追踪、候选关联、来源归属、属性（批注在「属性」的「批注」栏里）。

3. 图谱导览（12 步）

完整导览在「知识存储 › 记忆」的 DL-01…DL-12（针对阿里云示例库；69 已换真实湖仓数据，编号类操作同样适用）。核心操作一览：

步场景操作能看到
1图谱总览搜一个项目实体（如示例库的「宙渚智慧校园三期项目」），「距离」→「中心视图」，中心深度拖到 2 跳该项目两跳内的合同、付款、发票、单位和人员
2节点详情搜一份合同编号（如 HT-2022-0007），展开「属性」「来源归属」金额、签订 / 到期日期、风险等级、批注、数据来自哪个系统
3中心性与路径「图谱概览」看连接最多的节点；选中合同，在「路径追踪」填一个地区编号，点「追踪因果路径」合同经乙方单位（或所属项目）2 跳到达该地区
4去重与合并「实体解析」阈值 0.82 点「运行去重扫描」；「对比合并」填两个单位编号疑似重复节点对；名称不同但统一社会信用代码相同的单位

7时序底部时间轴竖线拖到某历史日期再拖回今天顶部「…个活跃」随时间变化；合同变更的历史金额

11词表浏览「词表浏览」左侧下拉框选概念体系，点树里的概念上下位层次（如「货物类合同」下有采购合同、销售合同、框架协议）
12查询与记忆打开记忆里的查询示例（CQ 系列），复制进查询页运行查询结果（如逾期付款节点和计划日期）

4. 搜索技巧与限制

  • 搜具体名称或编号最准：公司名、HT-2024-0001（编号精确命中）、HT-2024（编号前缀）。
  • 搜索词和某个标签完全相同（如「合同」「杭州市」）时，只返回那个完全相同的节点。
  • 中文按子串匹配：建议最多显示 6 条、结果 8 条，只在按 id 排序后最先匹配到的 200 个节点里挑（最多扫 12000 个）；常见词会被编号靠前的节点占满。
  • 路径追踪是有向的：从合同出发能找到单位、项目、地区、人员，反过来找不到。
  • 「…个活跃」少于节点总数：时间轴默认停在今天，不在有效期内的节点被隐藏。
  • 全图第一次加载并稳定 8000+ 节点：无 GPU 的机器约 60 秒，有显卡快得多。
  • 「加载本体 › 地址导入」不能用内网地址（服务器上不了外网），请用「文件上传」或粘贴内容。
  • 图谱刚被导入 / 推理写回后，统计类结果可能滞后几秒，稍后再查。

5. JupyterLab 抽取实验

全团队共用同一个 JupyterLab 和 /workspace（每人建议一个目录，如 /workspace/<姓名>/）。examples/ 里有两个示例 notebook：01_文档抽取（3 份合同 txt / docx / pdf → 大模型抽取 → 推图，42 秒）和 02_数据库抽取（SQLite 演示库 → DBIngestor → 行变节点、外键变边，31 秒）。

5.1 核心代码：semantica_lab

import semantica_lab as lab

text = lab.read_text("/workspace/examples/data/采购合同.docx")      # 支持 txt/md/docx/pdf/html/xlsx
result = lab.extract(text, entity_types=["单位", "人员", "金额"])   # 大模型抽实体和关系
payload = lab.payload_from_extraction(result, experiment="张三-合同抽取")
print(lab.push(payload))   # {'nodes_imported': …, 'edges_imported': …}
print(lab.stats())         # 当前节点数、边数
  • 大模型和 Explorer 的地址、Key 已在容器环境变量里配好，代码里不写密钥。
  • 数据库表或自己组装的图：用 lab.payload_from_graph(graph, experiment)。
  • 长文本自动分段（默认约 2048 字一段），输出装不下时自动对半拆开重试；extract(..., segment_chars=3000) 可自定。
  • 单次 push 不超过 50 MB，超了分批。

5.2 命名空间（实验名）

  • push 必须带实验名，建议「姓名-主题」（最长 64 字符，不能含 / \ " 和换行）。
  • 节点 id 自动加「实验名/」前缀：同一实验重复推送不翻倍，不同实验的同名实体互不覆盖。
  • 推进去的节点删不掉（上游没有删除接口）：先用小样本试，确认后再推全量。

5.3 用脚本跑

把 .py 放进 /workspace（JupyterLab 上传，或 SFTP 到服务器数据目录），然后：

docker exec semantica-lab python /workspace/xxx.py   # 有服务器账号（easter）
python /workspace/xxx.py                             # 没有账号：JupyterLab「文件 → 新建 → 终端」

容器里访问 Explorer 用 http://semantica-explorer:8000（默认值），不要用 18835（那是给浏览器的，要登录）。从自己电脑调接口：curl -u semantica:<密码> http://10.100.0.69:18835/api/graph/stats。

5.4 换模型

大模型网关默认 GLM-5.3，备选 Qwen3.8-27B：

result = lab.extract(text, model="Qwen3.8-27B")                 # 只换这一次

import dataclasses
settings = dataclasses.replace(lab.llm_settings(), llm_model="Qwen3.8-27B")
result = lab.extract(text, settings=settings)                    # 本 notebook 统一用

# 需要更细的抽取时：打开思考并放大额度（每份多等一两分钟）
settings = dataclasses.replace(lab.llm_settings(), llm_disable_thinking=False, llm_max_tokens=32768)

5.5 常见报错

报错开头处理
大模型返回了空内容 / 输出被截断保持关闭思考；调大 llm_max_tokens 或调小 segment_chars
调用大模型超时 / 网关出错 / 网关限流网关忙：稍后重试，少开并发，segment_chars=1000
…要求网关登录（HTTP 401）地址用了 18835，改回 http://semantica-explorer:8000
导入数据超过 50 MB 上限分批 push
…没有文字层，可能是扫描件先做 OCR

6. AgentScope「合同专家」

合同专家（GLM-5.3）通过 MCP 使用 Semantica 的 16 个工具：检索、实体与关系、统计、复杂查询、有效期、审批先例与决策、数据来源、团队记忆、本体、文本抽取、文档存取、数据库接入；也能写图谱。

使用步骤：

  1. 打开 http://10.100.0.69:18180 登录，进入 Chat 页（不要用 Sessions 页的 New session 表单，那是上游缺陷会报 400）。
  2. 选「合同专家」，新建对话，直接用中文提问。
  3. 回答先给结论，再列依据（实体编号、关键数值）；每次工具调用都记在会话事件里。

示例问法：

问法它通常用的工具
有哪些实体类型？合同有多少份？graph_schema、entity_stats
某单位（给编号 DW-0001）作为甲方的合同有多少份？按风险等级如何分布？entity_stats
HT-2022-0001 和 DW-0001 是什么关系？query_graph（mode=neighbors）
状态为已完成、且风险等级为高的合同有几份？entity_stats
与「工程施工合同 金额超过一千万 乙方资信 B 级」相似的历史审批先例有哪些？decisions
2025-06-30 仍然有效的合同有多少份？entity_stats（valid_at）
HT-2022-0015 的数据从哪来、谁改过？query_graph（provenance）
审核高风险合同要注意什么？search_memories

一个问题一般 10–60 秒，多数时间是大模型在想。

提问技巧与限制：

  • 给编号最准（HT-2024-0001、DW-0001）；只给名称时它会先换编号。
  • 想要可核对的结果就让它「列出编号」，关键结论按编号到 Explorer 再看一眼。
  • 关系有方向：「某单位作为甲方的合同」和「某单位签的合同」可能不一样，问清角色。
  • 所有人共用每分钟 120 次工具调用额度；它说「调用太频繁」时等几秒再问。
  • 写入直接生效：新增实体和关系、改属性、归档（删除即归档，可恢复）、登记审批决策。它写之前会先查编号、只用已有类型和方向、不覆盖已有实体；但关系写进去不能删除。让它写之前把内容说清楚，写完让它回读核对。
  • 图谱刚被改过时结果可能滞后几秒，稍后再问。
  • 它说「Semantica 暂时不可用」或「MCP 服务已被管理员暂时关闭」时，是服务在重启或被运维临时关掉，过会儿在同一对话再问；一直这样找运维。

7. MCP 接入自己的客户端

任何支持 Streamable HTTP 的 MCP 客户端都能接：地址 http://10.100.0.69:18835/mcp，鉴权 Authorization: Bearer <令牌>。

接入流程：

  1. 找运维建客户端并领取令牌：scripts/mcp-client.sh add <客户端id> editor "<显示名>" --profile compact（不要借用别人的令牌）。
  2. 按 MCP Streamable HTTP 无状态子集调用：只 POST、只收 JSON、GET 得 405 属正常、不支持批量；协商版本 2025-06-18。
  3. 令牌只从文件读，不要写进命令行（ps 能看到）或代码仓库。

Python 最小示例（python3 标准库）：

import json, urllib.request

URL = "http://10.100.0.69:18835/mcp"
TOKEN = open("<令牌文件路径>", encoding="utf-8").read().strip()
HEADERS = {"Content-Type": "application/json", "Accept": "application/json, text/event-stream",
           "MCP-Protocol-Version": "2025-06-18", "Authorization": "Bearer " + TOKEN}

def rpc(method, params=None, id_=1):
    body = {"jsonrpc": "2.0", "method": method, "params": params or {}}
    if id_ is not None:
        body["id"] = id_
    req = urllib.request.Request(URL, data=json.dumps(body).encode("utf-8"),
                                 headers=HEADERS, method="POST")
    with urllib.request.urlopen(req, timeout=180) as resp:
        raw = resp.read()
        return resp.status, (json.loads(raw) if raw else None)

status, init = rpc("initialize", {"protocolVersion": "2025-06-18", "capabilities": {},
                                  "clientInfo": {"name": "my-client", "version": "1"}})
print(status, init["result"]["serverInfo"])
rpc("notifications/initialized", id_=None)          # 通知：202
tools = rpc("tools/list", id_=2)[1]["result"]["tools"]
print(len(tools), [t["name"] for t in tools])
result = rpc("tools/call", {"name": "entity_stats",
                            "arguments": {"node_type": "合同", "group_by": "风险等级"},
                            "_meta": {"io.agentscope/toolCallId": "my-call-1"}}, id_=3)[1]["result"]
print(result["isError"], result["content"][0]["text"][:300])

现行工具目录（精简档 16 个：读 11、写 5）：

工具用法要点读写
graph_schema图谱概况 / 某类型属性和关系 / 本体 / 术语 / 变更提案（view 切换）；写查询前先调它读
find_entitiesquery 关键词检索；names 名称换编号（1–20 个）；text 从文字里找已有实体。三选一读
query_graphnode_id 必填；mode=node / neighbors（1–5 跳）；provenance 附数据来源读
entity_statsmode=aggregate 计数 / 分组 / 求和；valid_at 某日有效；changes 期间生效或失效读
cypher_query只读复杂查询（Neo4j 主库；Explorer 后端时为 sparql_query）读
graph_insightkind=analytics / quality / export读
decisions按情形找相似决策 / 按条件筛选；给 decision_id 看影响链（trace）读
reasoningmode=forward（事实+规则）/ abductive（反推假设）读
extracttext 抽实体和关系（scope=all/entities/relations）读
retrieve_context按问题检索已存文档的相关段落读
search_memories检索团队记忆（审核经验、查询示例、推理规则）读
write_decision登记审批决策；可关联两条已有决策（先例关系）写
manage_documentaction=store / update / remove 文档库写
write_entityaction=add / update / archive / restore 实体写
add_relationship新增关系（写进去不能删除）写
database_onboarding数据库接入：status / start（dryrun 默认，push 要 confirm=true；可 resume_job_id 续跑、带 review_edits）/ cancel写

调用约定：

  • AgentScope 里模型看到的工具名带前缀 semantica__<工具名>；Agent 定义里写不带前缀的名字。
  • 参数先由客户端按 inputSchema 严格校验（类型、枚举、多余的键都会被拒），对象里的过滤值一律写成字符串（数字也加引号）。
  • 结果是紧凑 JSON（键英文、值中文），列表统一 items / total / next_cursor；超长带 truncated: true 和 hint；没有结果不算错误（total: 0 + 改写建议）。
  • 业务失败：isError: true，正文是中文的可操作说明；未知工具：JSON-RPC -32602。
  • 浏览器页面不能直接调（Origin 检查）；每客户端每分钟 120 次；单次结果 2 万字符截断。

AgentScope 里再建一个智能体：推荐独立客户端做法——mcp-client.sh add <id> editor "<名称>" --profile compact 生成新令牌，在 Agent 所在命名空间建 Vault 和 static_bearer 凭据（target semantica），新 Agent 的 defaultVaultIds 指向它；mcp_toolset 里 16 个工具全部 enabled: true 且权限 always_allow（不写会默认 always_ask，Chat 页没有审批界面会挂死）。可运行参考：deploy/integrations/agentscope/setup_agentscope.py 和模板 agent-compact.json。改了定义要新建会话才生效。

8. 数据库接入（automap）

把关系数据库（MySQL / PostgreSQL 等）的表变成图谱：表 → 类、列 → 属性、外键 → 关系。流程：发起 → 演练（dryrun）→ 审核意见 → 续跑至通过 → 导入（push）。

智能体（合同专家）可以直接走完全流程，也可以用 MCP 的 database_onboarding 工具：

用法做什么
action=start，给 source、dataset、id_prefix发起接入作业；默认 mode=dryrun 只演练
action=status（可给 job_id）看进度和结果；演练没通过时 dry_run.failed_checks 带每项检查明细，next 给出续跑写法
action=start, resume_job_id=<id>在原作业目录续跑：快照、画像、共识等沿用，只重做受影响的步骤（湖仓合同从头约 1 小时，续跑 15–25 秒）
review_edits（随 start，只用于演练）审核意见数组（每条必须有 reason；常用 table / column / value / fk），最多 50 条
action=start, mode=push, confirm=true真正导入（导入时不能再带审核意见）
action=cancel, job_id=<id>取消（导入那一步不能取消）

69 的真实湖仓合同（25,690 实体 / 56,123 关系）就是经这条链路导入的。

9. 注意事项（不要做的事）

  • 不要删改数据目录；/workspace 里只动自己的文件，不改别人的目录和 examples/ 原件。
  • 重置图谱会清空全团队的图、批注、本体工作区、记忆和溯源：要重置先在团队说好，由运维执行。
  • 不要随手点会改共享数据的按钮：「对比合并」的「确认合并」、「导入导出」的「上传到图谱」、本体管理的「从注册表移除」「删除对齐」「批准」「发布」。
  • 推理演练的「将推理结果写入图谱」默认打开：结论会作为关系写进共享图且删不掉；只想看结果先关掉开关。
  • 不要在 notebook 和脚本里写密钥或数据库密码（用环境变量）。
  • 用完关闭 JupyterLab 内核：lab 容器 16 GB 内存 / 16 核，全员共用。
  • MCP 令牌不要写进命令行、代码或仓库；不要借用其他客户端的令牌。
